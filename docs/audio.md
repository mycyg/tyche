# 声音与角色配音

Tyche 在制作机离线生成声音，浏览器按需播放静态音频。玩家不下载模型，不连接本地推理接口，也不需要 API 密钥。

## 音乐与音效

`public/audio/music/` 包含八首原创程序合成曲目。共同的六音动机随场景改变节奏、和声与配器；没有采样商业游戏音乐或人声。

| 文件 | 场景 |
| --- | --- |
| `title.mp3` | 标题与开局 |
| `day.mp3` | 白天病区 |
| `night.mp3` | 夜班 |
| `pressure.mp3` | 后期高压值班 |
| `fracture.mp3` | 精神状态失真 |
| `inquiry.mp3` | 医疗纠纷复核 |
| `ending-calm.mp3` | 正常结业与职业选择 |
| `ending-dark.mp3` | 损害、离岗与追责结局 |

音乐由 `scripts/compose-score.py` 生成，发布格式为 32 kHz、立体声、96 kbps MP3。按键、翻页和掷骰提示音由浏览器合成。

## 台词与播放

`scripts/collect-voice.ts` 从实际内容库、病例变体、事件结果、手册和界面提取台词，输出 `docs/voice-cues.json`。显示文字与发音文字分离：金额、缩写、单位、范围和比较符号转换为可读音节，但不改变正文或数值。

中文以人物和动作为主语，少用状语和副词。否定、次日预约、费用归属等影响理解的限定保留。角色对白与场景旁白分段播放，人物头像不决定旁白声线；病历引文、诊断名称和按钮名称不作为人物对白。条件键、内部标记和异常日志不进入录音清单。

`voiceKey` 由角色与规范化原文生成。音频文件名使用同一键；`textSha256` 校验发音文本，修改单位读法后会补录，不把同名旧音频当成完成。完整句优先播放；床号、姓名和金额等动态句可按原文顺序拼接已录制片段。拼接必须覆盖整句，不允许跳过未匹配内容。

完整质检清单在 `public/audio/voice/manifest.json`；播放索引在同目录的 `index.json`，记录文件名、显示文字、角色和缓存版本。缓存版本取自录音文件的校验值；同一句补录后，请求地址随录音更新，避免浏览器播放缓存中的旧片段。播放端按需加载当前句子的 MP3，不下载所有人声。切换对话、关闭窗口或进入后台会终止旧的播放任务。成功与失败台词分别匹配，不在失败后播出成功录音。网络加载失败或资源缺失时可使用系统中文语音兜底；兜底不计入离线配音完整率。

音乐、对白和音效独立开关与调节音量。音频在首次点击或按键后启动；对白播放时，音乐音量降至原设定的 26%，结束后恢复。场景音乐交叉淡入淡出，音量始终限制在有效范围内。静音不妨碍完成游戏。

## 质量与完整性检查

- 生成器检查非空、有效采样、时长、峰值与削波比例；清单原子写入，允许中断后续录。
- `scripts/audit-voice.py` 使用本地 [Qwen3-ASR](https://huggingface.co/Qwen/Qwen3-ASR-1.7B) 转写，与发音文本比对。它是机器转写校验，不等于人工听审；低相似度片段保留原文与转写待核。

抽查新录音时，可传入 `--input <制作队列>`，只从该批已回传的片段取样；加 `--wait` 后，等该队列的文本及声线均已回传再取样。单位在录制前展开，包括毫摩尔、毫摩尔每小时、厘米、毫米、克、升及小时，电解质上标展开为钾离子、钠离子、氯离子及碳酸氢根；显示文本保持原单位。转写中的同音字差异不能单独证明错读，否定、数量、单位或称谓差异须复核。离子名称的出现次数不一致时，即使全文相似度超过门槛也保留听审。
- 专名、否定词、金额、药名、剂量与单位需要重点核对。中文数字与阿拉伯数字、同音字会造成误报，不能只靠相似度自动判定。
- 发布覆盖按当前 cue 文本校验值与实际文件统计；动态拼接另行验证，不以历史生成文件总数充当已覆盖台词数。

CUDA 制作使用 Python 3.12、PyTorch 2.9.1 + CUDA 12.8、Qwen TTS 0.1.1 与 FFmpeg。上述声线表供 CUDA 制作使用，切换声线后不沿用旧录音的制作校验。MLX 制作脚本另行保留。制作目录、模型缓存、密钥和临时音频不进入网页构建。

## Windows 离线制作

制作根目录为 `E:\TycheAudio`。`scripts/voice-environment.ps1` 将 Python、虚拟环境、下载缓存、模型缓存、CUDA 缓存、临时文件和输出定位到 E 盘，只修改当前制作进程的环境，不改系统 PATH 或注册表。运行制作命令前须在同一个 PowerShell 进程载入该脚本。

`scripts/setup-voice.ps1` 校验 uv 安装包，建立独立 Python 环境，并执行 BF16 显卡计算和依赖导入检查。PyTorch 使用官方 CUDA 12.8 软件包索引；普通 Python 依赖使用清华 PyPI 镜像。PyPI 镜像不等于 Hugging Face 模型镜像。环境检查不会下载模型或合成语音。

`scripts/probe-voice.py --model <E盘模型目录>` 在关闭在线访问的条件下加载本地模型，确认游戏所用声线存在，并报告显存占用。传输后直接做加载检查，不重复逐文件核对；它不调用语音生成方法，不输出试音或台词录音。

模型固定为 `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`，提交 `0c0e3051f131929182e2c023b9537f8b1c68adfe`。优先把本机已取得的完整 CUDA 权重经内网传到 E 盘。`scripts/download-voice-model.py --output <模型目录>` 可在来源机器下载官方权重并生成传输清单；MLX 量化权重不能直接作为此 CUDA 模型使用。传输后直接加载，正常生成只检查文件存在及大小，不重复计算整套权重哈希；怀疑文件损坏时才使用 `--verify-model`。推理期间关闭在线模型访问。

下载器按所选端点提供的 LFS SHA-256 或 Git blob ID 核对文件，并记录元数据端点。`--transport http --workers 8` 使用最多八路分块下载；HF/Xet 的半成品与 HTTP 分块各自保留。`--endpoint https://hf-mirror.com` 可选择第三方 HF 镜像，它不是清华 PyPI 镜像；镜像模式的文件和元数据均取自该镜像，不要求另行连接官方站点，也不发送本机保存的 HF 凭据。

`scripts/render-voice-cuda.py` 的正常生成必须提供 `--copy-review`。审核文件须有 `status: "ready-for-voice"`，并以 `cuesSha256` 指定已完成台词修订的采集文件完整 SHA-256；任何字节变化都会使检查失败。采集脚本不自动出具此审核文件。`--dry-run` 仅检查输入、模型和待生成数量，不加载模型或发出声音。

只有台词修订结束后才建立审核文件并生成。短句试音也遵循这一顺序。断点续录同时校验发音文本、角色、预置声线、表演指令、模型提交、生成参数、编码参数与 MP3 文件校验值；修改过的台词必须重新配音，不能凭相同文件名跳过。

已修订台词通过 `scripts/queue-voice.ts` 按现存录音生成增量队列，优先处理人物对白与事件反馈，未改动的录音复用。主队列运行时，传入 `--after <主队列>` 可建立补录队列，不重复安排主队列中尚未完成的相同台词。主队列全部回传后再执行补录，避免同名文件先后覆盖影响传输。CUDA 生成期间，`scripts/sync-voice.ts --host <制作机> --input <队列文件> --watch` 每二十秒取回已完成片段。回传比较文本、角色与清单中已有的录音校验值；同文重录也会替换，未改动片段保留，不扫描模型或逐文件计算哈希。连接信息由命令参数提供，不存入文档或脚本。

患者病例中的家属引语按发言者分配声线，不按患者性别分配。独立成行的患者引语使用患者声线，病史、支付方式和动作叙述使用旁白；采集与界面共用 `dialogueSegments`。重点病例另用 `clinicalVoiceActor` 区分问诊回答、医生告知与记录引文；反馈从已提交操作取发言角色，不从当前地图人物取声线。

`python3 -m unittest discover -s scripts -p 'test_voice_cuda.py'` 检查台词锁、旧录音失效、角色输入和模型传输校验，不导入推理库，不生成音频。实际显卡加载、配音速度、转写与听审须另行验证。

## Linux CUDA 制作

`scripts/setup-voice.sh <绝对制作目录>` 建立独立 Python 3.12 环境，安装 CUDA PyTorch、Qwen TTS 和编码依赖。使用现有 `uv` 与 Python 时，可通过 `TYCHE_UV`、`TYCHE_PYTHON` 指定路径；不使用 sudo，不替换系统 Python。模型、输出和临时文件放在该制作目录下。

3090 使用 BF16 与 SDPA，先从 `--batch-size 4` 开始。模型可复用内网传入的同一份 CustomVoice 权重；没有可用副本时从指定 HF 镜像下载。用 `probe-voice.py --model <模型目录>` 检查实际显卡加载；不重复核对整套模型，不重录已有成品。

生成继续使用 `render-voice-cuda.py` 和已修订的增量台词队列。回传命令为 `npx tsx scripts/sync-voice.ts --host <制作机> --remote-root <绝对制作目录> --input <队列文件> --watch`，自动采用 Linux `tar` 与该目录下的 `output`；省略 `--remote-root` 时保留 Windows E 盘默认路径。账号、地址和凭据不写入仓库。

## 播放索引与发布验收

`npx tsx scripts/finalize-voice.ts` 根据当前 `docs/voice-cues.json` 与完整质检清单原子重建 `public/audio/voice/index.json`，并输出 `docs/audio-build-report.json`。它不启动生成或转写进程，不删除旧录音，也不改写质检清单。

进入播放索引必须同时满足：发音文字的 SHA-256 与当前 cue 一致、角色一致、MP3 文件位于指定目录且非空。质检清单提供文件校验值时，还要核对实际文件内容。旧文本、缺文件、正在替换且校验值不一致的文件均不计入覆盖；不在当前 cue 集合内的历史素材仍保留在磁盘，但不进入索引。显示文字取自当前 cue，而不是旧质检条目的文案。

发布前依次完成台词采集、增量生成、质检，再运行 `npx tsx scripts/finalize-voice.ts --require-complete`。缺少任一当前 cue 时，该命令返回失败退出码；生成部分索引不代表验收通过。之后才能执行构建和发布。构建期间若继续改文案，必须重新采集、补录并重建索引。动态姓名、床号、金额的完整拼接与真实界面朗读需另外验收，静态 cue 全覆盖不替代实际播放检查。

报告的 `estimatedFinalVoiceBytes` 按已匹配 MP3 的每个发音字符平均字节数推算全部 cue 的音频体积，只是估计。采集列表按角色和句长排序，不能用短句的平均文件大小乘剩余句数来宣称最终体积。

生产构建按播放索引收录当前 MP3，并加入八首场景音乐、网页美术、程序和索引。试音、质检清单、未引用的历史 MP3 仍保留在制作目录，不进入 `dist`。构建拒绝越界路径、符号链接和缺失资产；网页静态资产以 900 MiB 为保护上限。最终仍以完整构建后的整个 `dist` 目录为准，未生成内容不计作零字节，也不能据此放行发布。

[GitHub Pages 官方限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)规定发布站点不得超过 1 GB，源仓库建议不超过 1 GB，月带宽软限制为 100 GB。自定义 Actions 工作流免除的是每小时十次构建的软限制，不是站点体积限制。超过发布上限时，应先确定新的音频分发方案或经听审验证的编码方案；不能删除台词、改用系统朗读充数，或自动清理原始素材来掩盖缺口。
