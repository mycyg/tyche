# 完整病例导入差异（2026-09-07）

## 这份文件在说什么

20 个完整病例的玩法数据放在 `src/content/clinical/graphs.json`，由 `scripts/import-clinical.ts` 从设计文档 `04_病例库/*.md` 解析生成。上一轮文案审读没有跑导入脚本，而是直接改了 `graphs.json` 里的字符串，改动没有回到设计文档。这样一来，任何人重新执行导入都会把那批文案覆盖掉。

本次先把导入结果写到临时文件，与仓库里的 `graphs.json` 逐字段比对，确认差异的来源，再把属于内容的改动回写进设计文档，把属于规则的改动留在投影层，最后重新导入。**现在设计文档与 `graphs.json` 已经一致，重新执行导入不会再丢文案。**

## 比对方法

1. 复制 `scripts/import-clinical.ts` 为临时脚本，只改输出路径，把 20 例解析结果写到临时文件，不覆盖 `graphs.json`。
2. 把两份 JSON 展开成叶子路径字典（约 20,353 个叶子），逐路径比较。
3. 对象键、数组长度、以及全部非字符串值（ID、条件、检定、隐患权重、费用、AP、分钟、`next`）**零差异**，只有玩家可见的字符串不同。

### 类型一：行动回报（367 处，其中 355 处设计文档原本没有写）

设计文档里，大多数选项只有一行表格，没有写这个动作做完之后玩家看到什么。解析器碰到空回报时，用 `normalize.ts` 的兜底把选项文本加个句号当作回报（`o.result=o.result||o.label+'。'`）。上一轮把这批兜底文案改写成了完整的句子。

例（C001 s1_history）：兜底为「追问起病经过与既往有无包块。」，手改后为「你追问起病经过与既往有无包块。」；C001 s5_admit 兜底为「收儿内科观察，天亮再请会诊。」，手改后为「你把孩子收入儿内科观察，准备天亮后再请会诊。」。

**处理**：全部回写进 `04_病例库/*.md`，写成设计文档已有的叙述行格式 `叙事（选项 ID）：……`，放在该节点选项表之后。设计文档从此对每个选项都写明了回报。

另有 4 处（C002 `s1_allergy`、C005 `s2_neuro`、C005 `s2_vision`、C007 `s2_throat`）原本在「设置 flag」列里写了电报体的 `（回报：无已知过敏）`。这类缩写已从表格里去掉，改由叙述行承担完整句子。

还有 6 处属于 `normalize.ts` 用 `add()` 造出来的选项（C003 `s3_observe`、C003 `s3_rescue_fluid`、C007 `s5_return_only`、C009 `s4_redraw`、C011 `s1_exam_labs`、C013 `s1_wife_out`），设计文档表格里没有这些行，回报文案留在 `normalize.ts`。

### 类型二：检定成功与失败回报（34 + 53 处）

设计文档把这两段写在「检定」列里，用的是电报体，并且把结算数值直接写进了玩家能看到的句子。

例：C001 `s2_abd` 失败原为「记录「腹胀，肠鸣音减弱」」，手改后为「你记下了「腹胀，肠鸣音减弱」。」；C001 `s5_inform` 失败原为「母亲要求「先输液看看」，情绪 −5」，手改后为「母亲还是要求「先输液看看」。你有些沮丧。」——数值效果仍保留在效果字段里，只是不再出现在对白中。

**处理**：回写进设计文档，格式为 `台词（选项 ID 成功）：……` 与 `台词（选项 ID 失败）：……`。

### 类型三：节点与结局正文（14 处）

**处理**：全部改在 `04_病例库/*.md` 的场景行、`（叙事档：……）` 标题参数或结局分支表格单元格里。

## 顺带修的解析器问题

1. 叙述行原先用 `dialogue[1].includes(o.id)` 匹配选项，`s6_transfer_note` 会连带命中 `s6_transfer`。20 例里有 10 组这样的选项 ID（C001 s6、C003 s4、C005 s1bag／s3、C011 s1、C014 s4、C019 s4），目前设计文档没有踩到，但补写叙述行会踩到。改为按分隔符切分后精确匹配选项 ID。
2. 化验回报的扫读行原先只认行首的 `[扫读]`，C011—C016 六例写成了 `- 扫读：「[扫读] ……」`，解析不到，扫读版退化为全文。改为容忍这层包裹。
3. 隐患理由原先在设计文档缺少鉴定书行时静默改用选项文本。改为在导入时抛错并列出缺行的选项。
