# 架构与内容扩展

## 运行边界

Vite + TypeScript + Preact 单页静态应用，基路径 `/tyche/`。Three.js 只在掷骰时动态加载，场景和人物均为 2D 资源。没有服务端、登录、上传患者资料或在线文本生成。

`WorldStage.tsx` 用 Canvas 绘制可行走的像素医院。`world/layout.ts` 定义 1536 × 512 地图中的 12 个房间，地图绘制、房间入口和碰撞共用布局数据；`navigation.ts` 负责可行走区域、路径与移动。A、B、C 病房共 12 张住院床，床号为五床至十六床。护士站、主任办公室、药房、急救室、档案室、值班室、家属谈话室、科研室和留观室沿走廊分布。

地图中的床位目标从运行快照生成，患者身份、床号与在院状态不由场景另造。满床时患者留观等待，住院床释放后按状态机规则安排；留观不能冒充已占用住院床。人物靠近目标后打开床旁、剧情或交班交互，主场景持续保留医院空间。

```text
Card + Choice → 确认 → 纯状态机结算 → 保存结果
                                 ├─ 资金缺口 / 首次体力归零
                                 ├─ 掷骰演出 → 结果
                                 └─ 下一节点 / 次日 / 鉴定庭 / 结局
```

`src/game/engine.ts` 不依赖 DOM。`act(state, action)` 返回新快照；不合法或重复指令返回原快照。`committed` 保存实例化后的选择 ID。动画只展示已持久化结果，不决定骰面。

处置检定与日终共用 `Dice.tsx`。拖动松手提供演出速度，点击或回车也能投掷；Three.js 展示二十面骰的旋转、弹跳和落定。交互、动画结束与继续操作不重新生成随机数，结果只由状态机提交一次。减少动态效果时缩短演出；WebGL 初始化失败或上下文丢失时具有文字骰面回退路径。

`random(seed,key)` 使用稳定哈希。独立键覆盖重点病例、短事件、支线同日顺序、选项排序、住院时长、提前出院回院、日终、debuff 和鉴定庭。插入一个无关节点不会消耗另一节点的随机数。

## 内容作用域

患者使用局内唯一 `uid`；同一病例、同一实体的两次就诊分别保留实例。夜间急诊有独立实例，不能把随机急诊的后果累积到白天那名患者。`damage` 记录已经发生的损害，`mitigated` 记录已处理部分，`stability` 记录恢复进度。出院评估须同时满足诊疗节点已结束、没有未处理损害、恢复进度达标，再由玩家支付行动并完成交接。

隐患必须包含 `scope.kind / scope.id`、选择 ID、当时文字、日次、类型、权重、制度依据及因果属性。科研卷宗使用 project scope；人情与贷款使用 personal scope。项目不实不能成为其他患者的临床 R、死亡或医疗损害刑事理由。

事实记录有源选择、日次和序号。持有原件、已提交原件、知道问题、实际使用、已经付款、收到还款、岗位确认分开设 flag。承诺不视作兑现，申请不视作获批；失败检定只写失败分支的实际事实。

## 病例合同

`src/content/clinical/graphs.json` 包含 20 份完整病例图，134 个节点、558 个选项。图内有条件分支、多选、重复检查限制和独立结局；`clinical-a.json`、`clinical-b.json` 仍提供基础病例资料和兼容字段。208 份病例预设在 `src/content/patients/` 编译，251 位患者实体按身份与就诊情境匹配。病历初诊只显示来源已知资料；实际选择的检查结果逐条加入已知信息。

病例预算和既有费用必须对应该例。病例库内的医疗文本是游戏情节，不是医学教育题库或诊疗软件。

床旁显示对应病例的患者画像；`RecordBook.tsx` 按患者作用域分页展示入院登记、问诊与检查、处置与交班、费用。问诊和处置内容取自已发生的日志，未做检查显示未留下记录，不能从病例预设直接补齐。入院日、实际住院天数（LOS）、预计住院天数、累计诊疗费、当前预算与实际垫付均读取患者状态。诊疗费首先记入病例账，病组预算不是个人收入；超出预算的自付和预算调整后的退款由费用逻辑计算。

新局的四条暗黑链由 `src/content/events/butterfly.ts` 与 `director.ts` 调度，包括 32 个节点、3 个汇合场景与 20 个链内收口。`stories.ts` 中的 35 个节点保留旧档接续，带旧 `seen` 事实的存档按原链推进；新局不同时重复投放旧链与替代链。兼容节点的文本和音频仍需校验，不计入新局节点可达率。

事件目录包含 212 个事件，另有 20 张电车难题及绑定原对象的回访。天赋目录包含 30 项天赋、24 项持续状态；结局目录为 X01—X41，主项、附项和彩蛋按资格与优先级组合。目录数量不证明自然流程可达，逐节点路线证据单独验收。

添加内容需运行 `npm run check:content` 和状态机测试；增加结局也须同步结局簿。禁用未经选择便发生的投稿、签名、收款、导出和抢救；禁止自伤方法与步骤；不复制其他游戏原句。

## 存档

`tyche.save.1` 保存完整运行快照、成长和设置；`tyche.backup.1` 保存上一份通过校验的存档。编码包含 schema 与校验和。先解析与验证，后导入；导入需玩家明确确认。损坏数据不覆盖健康备份。存储配额或隐私模式失败时，状态继续保留在内存并提示导出。

地图位置保存在运行快照中。带教状态作为存档中的独立 `guide` 字段保存，含版本、启用状态与已观察事件；解析时校验版本和事件名，不参与随机数或回合数计算。

校验和用于检测损坏，不是防作弊签名。单机存档不承担对抗篡改或排行榜公平性的责任。客户端渲染使用文本转义，不把存档字符串作为 HTML 执行。

## 可访问性与移动端

桌面和横竖屏均以可行走地图为主场景，HUD、床旁和病历窗口按可用宽高排布。支持 WASD / 方向键、点击寻路、触屏摇杆、E / 空格交互、J 病历、1—4 选择与可返回弹窗 Esc。病历分页支持左右方向键和 Home / End。主要按钮提供触控尺寸、焦点返回、文本状态读出、大号文字与系统减少动效。正文没有限时阅读、闪烁惩罚或长按才能完成的操作。

带教步骤条占用独立 HUD 空间，从靠近病床、打开病历、确认处置到查看检定和交班，只有对应真实行为才能推进。选择无需检定的处置时，骰子目标标为无需掷骰。玩家可以跳过或在设置中重新开始；术语手册复用 `copy.ts` 的 `TERM_GUIDE`，解释行动、精神、预算、自付、骰子门槛、预支与透支。

声音包含八种场景音乐、离线角色配音和合成操作音，三个开关与音量独立保存。播放器在用户手势后启动，页面隐藏时暂停，对白期间降低音乐音量。运行时只读语音索引中的文件；未覆盖台词不会调用在线模型补写。静态页面不请求麦克风或相机。配音覆盖与抽听状态见声音验收记录。

## 工具链与替代实现

- 内容作者编辑 Markdown 设计库；导入脚本生成 JSON，TypeScript 提供类型约束，`check-content.ts` 检查结构、条件、身份兼容与来源。采用这条管线替代 YAML 与 Zod，避免维护第二套内容原稿。
- 界面使用 Preact hooks 管理保存快照，状态变更统一经过 `act` 与存档入口。没有引入 Signals。骰子使用 Three.js 的受控演出，不用 Cannon 的物理结果决定骰面。
- `tsconfig.engine.json` 不加载 DOM 与 Node 类型。纯度测试检查运行依赖是否引用界面、系统时钟、计时器或未设种子的随机数。`structuredClone` 只声明跨宿主的克隆合同；存储通过 `SaveStorage` 端口传入。
- UI 创建本局实例 ID，传给 `startRun`；运行引擎的默认 ID 只依赖种子及周目。随机键剥离实例前缀，收藏领奖按实例去重。
- Biome 检查错误控制流、重复键和受限依赖；TypeScript 检查应用、引擎和构建脚本。Vitest 与 Playwright 分别使用独立配置，浏览器项目包括 Chromium 和 WebKit 的桌面／横竖屏。
- Vite 的生产构建关闭默认整目录复制，按语音索引及音乐目录生成资产清单。历史音轨、试音和生成清单不进入 `dist`；源文件不删除。站点资产超过 900 MiB 时构建拒绝继续。
- `.nvmrc` 固定 Node 主版本。开发命令记在 README；不增加仅供某个编辑器使用的启动配置。仓库级代理约束统一维护在 `AGENTS.md`。

## 可选 WebMCP

支持该提案的浏览器中注册 `read_tyche_turn`、`confirm_tyche_choice`、`advance_tyche_turn`。它们调用同一个状态机；读取不泄漏未来结果或提前展示隐患，写操作校验当前阶段及选项 ID。没有新建/覆盖轮转的自动工具。没有该接口的浏览器照常游玩。
