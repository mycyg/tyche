# 验证范围

工作区按批次收集程序化验收证据，未覆盖路径继续保留缺项。历史构建的测试和游玩记录不能替代当前工作区结果。问题归类及最新结果见 [审查台账](review-triage-2026-09-06.md)，人工轮次见 [游玩台账](playtest-ledger.md)。

## 验收顺序

1. 收齐报告涉及的代码、数据、指引和文本修改，补齐回归用例。
2. 运行 lint、引擎及工具类型检查、单元与集成测试、内容校验、整局模拟和生产构建。
3. 全节点检查留下真实开局参数、动作序列、条件来源与复演结果。强设资源、节点或标记的夹具仅用于边界测试，不能计入自然可达覆盖。
4. 程序化验收通过后，试玩关键病例、事件链、不同结局、存档和手机横竖屏。一轮内记录问题，结束后按共同原因修复，再回归相关范围。
5. 按最终文本生成配音，核对完整索引、动态句与抽听结果。发布门禁及线上版本另行核对。

## 检查边界

内容清单包含 20 个完整病例、208 个预设、251 位患者实体、212 个事件、4 条暗黑链、3 个汇合场景、20 张电车难题来源卡、30 项天赋、24 项持续状态及 X01—X41。库中存在一个 ID，不等于它已通过触发、后果、存档和画面检查。

模型遍历检查条件与出口；真实引擎路线检查资源、日期、患者和事实来源；浏览器检查画面、操作与实际播放。三类证据分别报告。读取隐藏数据的模拟策略不代表玩家胜率。

`npm run check:routes -- 100 --require-complete` 从零周目成长、开局实际九张天赋牌及合法动作出发，保存每局选择、奖励与购买记录，并重新复演整个成长序列。覆盖报告分别列出已提交节点、仅显示节点、未覆盖项和失败动作；不存在完整覆盖时，严格命令返回失败。可用 `--replay <记录目录>` 独立复演，源代码校验值不符时拒绝沿用旧证据。

加 `--branches 120` 可在真实到达的病例／事件检查点尝试互斥选项；每个分支包含所属完整路线、开局后的动作位置、检查点校验值与分支动作。复演先重走实际前缀，再重走分支，不装载任意构造的患者、资源或标记。完整路线动作、探索步数、保存的分支前缀及复演动作分别计数；分支不贡献周目奖励，也不计为额外完整游玩。到达预算上限但仍缺覆盖时保持失败。

Playwright 配置包含桌面 Chromium、竖屏 Chromium，以及 WebKit 的手机横、竖屏；这是浏览器模拟，不是实体手机验收。缺少浏览器或 WebGL 环境时保留未验证状态，不改用纯函数通过数替代。

配音以当前台词校验值为准，旧录音和系统语音兜底不计完整率。发布保留完整配音检查，缺少当前台词时不能上线该构建。
