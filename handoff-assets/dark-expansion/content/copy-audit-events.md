## 事实、因果与说话人约束

| 对象 | 保留的事实与关系 |
|---|---|
| 患者和家属 | 患者病情、检查、单位、用药、亲属关系、是否能表达、患者授权范围保持原样。没有将家属录音写成恶意或犯罪。 |
| 费用 | 医疗账单、个人超支、科室支出、私人借款、同事应还本金分别表述。退还未接受款项不扣生活费；借到钱不等于已替家里缴费。 |
| 时间 | 选择、约定、实际到场、完成、回执、到账分别表述。已有临床期限、借款期限、逾期后果、数组数量与规则数值不改。 |
| 记录 | 不把补记写成原先存在的记录，不把手持原件写成已经提交，不把同意作证写成到场，不把普通咨询写成认定过错。 |
| 主角 | 叙述中的“你”始终为玩家医生。临床责任、付款与签字不转给他人。 |
| 李恂 | 借款人、互助者、特定查体的当事人。只完成本人有条件完成的任务，不替玩家承担其他责任。 |
| 姜蓉 | 护士长；负责协调、见证、护理相关工作。不会因为协调接班而变成实际接诊医生。 |
| 周乔 | 科研协作者；只确认本人核查和贡献，不替玩家答复投稿责任。单独核查与共同核查共用的结果使用“你发现”，避免虚构她到场。 |
| 唐济、叶茗 | 主任和药代的实际要求、邀请、资金来源与利益冲突保留。没有把拒绝邀请的失败写成默认接受。 |
| 家人 | 父母、弟弟与伴侣不混用代称；家里付的钱不算玩家个人付款，家人代办不算代签或已缴费。 |

## 投影与主任务核对项

事件正文依次经过 `authored.json`、`EVENT_DIALOGUE`、`eventToCard`，随后可能由费用、人物身份、历史记录与天赋适配继续替换。选项结果主要取 `EVENT_RESULTS`、`EVENT_FAILURES`、`EVENT_DEFERRED_RESULTS`。支线结果优先取 `BUTTERFLY_CHOICE_RESULTS`，并可能由 `src/game/director.ts` 再次覆盖。只改源正文不能覆盖这些入口。

1. `src/game/director.ts` 的 `makeButterflyCard`（约 905–954 行）及汇合场景（约 1090 行）仍需由负责 game 目录的主任务审读：全额还款、无钱退款、归还改期、答辩失败、N02/N06/N08、科内教学 N01/N05 均存在独立结果或正文。该文件不在本次修改范围。
2. `catalog.ts` 的 `eventWeight` 使用 `title + text` 匹配“投诉|拍照|录音”，`audit-echo.ts` 也依据标题/触发串匹配审计词。本次保留会影响匹配的词；没有改权重机制。
3. `authored.json` 的 `trigger`、`consequence`、`followup`、`requires`、`cost`、`rules`、`outcome` 及来源数据全部保留。它们含被解析的中文公式或条件，不能当普通对白批量替换。`merges.text` 是被 director 覆盖的来源说明，未当作正式玩家正文重写。
4. `butterfly.ts` 用“互助已兑现”“人情未用”“已投稿”等中文前缀选择尾声段落；这些前缀与 `authored.json` 中对应前缀均保留。
5. E-064 的源正文原称“月底还”，但规则、展示按钮、已有结果和结算均为七天后归还。本次只把正文对齐现有七天期限，未改变到期日。
6. E-091 的结果原同时写“周末补班”和“明天安排”，既有延后执行为次日；本次移除不一致的“周末”，保留明天补班。
7. 数字文案与源机制不一致而已有动态覆盖的场景仍以动态覆盖为准，例如 E-100 的 ICU 每日实际补缴、E-144 三位加号患者、E-159/E-160 累计扣款。主任务新增投影时应继续保留实际金额与实际患者数。
8. 旧存档中已经发布或记录的卡片可能保存旧文本；本次没有重写存档、日志或音频索引。新生成卡片使用这里的文本，历史存档和语音同步需由主任务另行核对。
